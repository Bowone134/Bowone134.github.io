为什么建个人网站？

Emm..突然想到就来了（
好吧其实还是有一定诱因的。前几天我想着给电脑整个wsl，整完了又想着整个waydroid，结果整了有两三天，还没解决最后的网络访问问题。之后我想着再来看看，结果忘记了waydroid需要的一些服务wsl默认不自启，我也没记都是哪些服务要手动启动。最后我不得不把我整waydroid看到那些教程全都翻出来，一个个的手动启动。虽然最后把它们都写进文件里让waydroid启动的时候自己启动服务。但是这个过程也表明，有些东西还是记下来比较好。

我的经历

我已经将建站教程写进另一篇博客里了，这里就写一些我个人碰上的问题。

代码高亮不工作

在刚安装Hexo时，npm给我报了一个警告：

npm warn allow-scripts 1 package has install scripts not yet covered by allowScripts:
npm warn allow-scripts   hexo-util@3.3.0 (postinstall: npm run build:highlight)
npm warn allow-scripts
npm warn allow-scripts Run `npm approve-scripts --allow-scripts-pending` to review, or `npm approve-scripts <pkg>` to allow.

但很神奇的是，我在运行npm approve-scripts hexo-util@3.3.0后，它却提示No packages with unreviewed install scripts.。之后也多次碰上这种情况。之后我确认了一下，在第一次运行approve的时候就已经默认放行脚本运行了。但之后每次碰到相关包运行这些脚本时，npm会在已经放行的情况下照旧提示上面的警告。
什么玩意
总之这个放过了就无视就好。
之后，为了验证是否成功安装代码高亮，我写了测试文章，但代码没有高亮。在排查了老半天配置问题后我才发现：他们的代码块是用三个 ` 带语言名字包起来的，而我用了Markdown的原始代码块——在代码前用Tab键。正确的代码块如下： 

```cpp
#include <iostream>
using namespace std;

int main() {
    cout<<"Hello world!"<<endl;
    return 0;
}
``` # 在代码块里再写代码块好像会导致奇怪的问题，总之这个注释是为了阻止这个问题。

Man, what can I say?

其实，Hexo还有适用于引用、链接、图片等各种资源的标签插件（见标签插件 (Tag Plugins) | Hexo）。使用标签插件也可以创建代码块。

在给我的网站应用了snark主题后，我发现代码高亮又坏了。刚点进文章的时候，高亮还完全正常。下一秒就变成这个鬼样子：

解决方案？我其实不太明白到底是哪些选项冲突了。总之我单独开启了主题的highlight，把网站里的highlight和prism.js都关掉了。现在虽然没有代码行数，但至少高亮解决了（

Legacy JS API弃用

在运行本地网站时，总有一条提示要跳出来：

Deprecation Warning [legacy-js-api]: The legacy JS API is deprecated and will be removed in Dart Sass 2.0.0.

More info: https://sass-lang.com/d/legacy-js-api

话是这么说，但我也没看见哪里换api什么的。留着吧，又占控制台位置。
所以这件事交给了Copilot（
Copilot帮我修改了hexo-renderer-sass中使用旧版api的部分，并写成了patch。这样这个改动就是可移植的了。

主题不支持Giscus评论系统

在阅读了一堆教程，碰上一堆不支持和已弃用后，我最终决定给博客引入Giscus评论系统。虽然这个系统必须要Github账号才能使用，但别的我暂时搞不定（
但问题是，这个snark主题并没有原生支持Giscus而是Valine，而Valine又有后端托管网站即将停止支持的问题。我原先使用了hexo-generator-comments和hexo-comments-giscus插件，但是hexo-comments-giscus插件又只支持EJS (.ejs)， Nunjucks (.njk) 和 JSX + Inferno (.jsx) 模板引擎，snark用的又是Pug (.pug)。那怎么办？
于是，我选择直接在主题代码里添加对应代码。在snark/layout/_partial/comments.pug里，我找到了Valine的css和引入js的代码。所以我就直接复制黏贴一份，再把内容换成在Giscus网站上配置得到的js代码，内容如下： 

if theme.giscus.enable == true
    #gcomment
    script(src="https://giscus.app/client.js"
        data-repo="用户名/用户名.github.io"
        data-repo-id="仓库唯一id"
        data-category="评论系统使用的讨论名"
        data-category-id="讨论唯一id"
        data-mapping="pathname"
        data-strict="0"
        data-reactions-enabled="1"
        data-emit-metadata="0"
        data-input-position="top"
        data-theme="dark_dimmed"
        data-lang="zh-CN"
        data-loading="lazy"
        crossorigin="anonymous"
    )

而后，我在主题的_config.yml里，单独加了一条配置来开启Giscus: 

giscus:
  enable: true

现在评论系统就能正常工作了。

有账号却没法在Giscus系统下评论

当我解决了引入Giscus系统的问题后，我想着测试一下，于是就试着评论了一下。
但结果是，Discussions页面成功创建了对应页面的讨论，但评论本身没发出去。
在查看控制台后，我发现了这么一条报错： 

Access to fetch at 'https://api.github.com/graphql' from origin 'https://giscus.app' has been blocked by CORS policy: Permission was denied for this request to access the `loopback` address space.

想当然的，我以为是我在本地测试网页评论引起的问题。于是我将网站部署上线后再次尝试，却还是同一个结果。
问过Deepseek后，他认为我访问网站时仍旧是通过localhost访问的。而除了真的用localhost访问外，使用内网穿透或本地代理同样会出现这个情况。
在ds指导下，我总算想起来罪魁祸首是谁了：Steamcommunity302。
Steamcommunity302在工作的时候，会将需要加速的网站全都解析到127.0.0.1，然后进行转发。（这部分我猜的，我也不知道具体原理，别真信x）
总之，解决方案就是，要么别本地代理，要么直接访问。
虽然也有取消回环限制的做法，但是既然有回环限制那一定有他的道理，就不碰了。
