如何借助Hexo和GitHub Pages搭建个人博客

2026-07-15Tutorial • Internet • Website • Setup

建站过程

借助Github Pages部署个人博客的过程如下：

  • 注册Github账号
  • 创建特定名称的仓库
  • 选择建站方式

第一步如题。
第二步的创建特定名称的仓库，要求一定要是你的用户名.github.io。
第三步中的建站方式，在本文中就是Hexo。Hexo具有庞大的生态和丰富的主题和插件，对于新手来说十分友好。

安装Hexo和相关插件

参考资料：文档 | Hexo

首先是安装Git和Node.js。
Git:
在Git官方页面选择适合你操作系统的方法安装。
Node.js:
在Node.js官方页面选择适合你操作系统的方法安装。

装完使用npm install -g hexo-cli安装Hexo，再在准备放项目的文件夹里运行hexo init my-blog（”my-blog”为项目文件夹名字）。之后进入该文件夹，输入npm install安装hexo的相关module。
在安装过程中，有可能碰上提示found vulnerables，这时候一般按照提示运行npm approve-scripts <pkg>就能自动解决。

另：如果你想将项目也上传到Github，首先最好不要让项目和网页在同一个仓库里。（举例子，网站的仓库为name.github.io，那么项目的仓库就另建一个。）其次不要将各种缓存、node.js模块和静态页面也上传到项目仓库里。作为参考，以下是我项目仓库的.gitignore文件： 

node_modules/
public/
.cache/
db.json
.DS_Store
.deploy_git/

网站设置

参考资料：配置 | Hexo

在_config.yml中，一般会修改以下选项。 

title: 你的网站名字
author: 网站作者名字

url: 网站链接，在本文中使用Github Pages，故使用 https://你的用户名.github.io

还有其他选项，推荐先测试运行网站后，根据自己需求修改。

完成网站设置后，运行hexo s即可运行本地测试网页，在浏览器访问提示的网站即可查看网站。在控制台按Ctrl+C即停止运行。

博客编辑

参考资料：写作 | Hexo

在控制台中输入hexo new "文章标题"即可创建文章。新文章放在source/_posts/下。新建的文章一般带有文章头，比如下面这个： 

---
title: {{ title }}
date: {{ date }}
categories:
tags:
---

title和date一般不用改，categories和tags为文章分类和标签，按需填加。
在文章头下面，就是写文章内容的区域，正常按照md格式写就行。
写完后记得运行本地网页查看效果（如果已经在运行了，也不需要重启，刷新即可获取你的更新。）

Github Pages部署网站

参考资料：Quickstart for GitHub Pages - GitHub Docs

如前文，在Github上新建一个名为你的用户名.github.io的仓库。
在项目里运行npm install hexo-deployer-git --save来安装部署插件。
安装后，在项目的_config.yml中找到deploy项（没有就自己写一条），修改选项为： 

deploy:
type: git
repo: https://github.com/用户名/用户名.github.io.git
branch: gh-pages
message: "Site updated: {{ now('DD HH:mm:ss') }}" # 可选

这时，你的项目部署设置就已经完成了。运行hexo g生成静态页面，生成的文件会放在public文件夹下。然后运行hexo deploy就能按照设置将静态网页推送至网站仓库里。
第一次部署时，你的Github Pages应该还没有配置。在仓库的Settings里面，点击Code and automation下的Pages选项。在Build and deployment下的Source里选择Deploy from a branch，并在Branch中选择分支为gh-pages，文件夹为根目录。点击Save后，你的网站应该自动部署在了你的用户名.github.io下。
在之后的部署中，只要运行deploy，Github都会自动进行部署。

自定义主题

Hexo拥有许多社区主题，也可以自己创建主题。这里只讲社区主题。
在 Themes | Hexo 下可以自己选择需要的主题，查看预览网页（一般是作者自己的博客，但也存在作者自己的博客里没用自己的主题的情况）。在对应主题的Github页面一般都有主题介绍和安装教程。
虽然选主题这种事情一般是你觉得哪个好看就选哪个，但是有的时候可能会导致你用不了某些插件（使用的对应插件不支持的渲染器之类的）。如果确实需要某些插件，就需要自己考虑是换主题还是自己写代码兼容了。如果实在担心，就优先选择使用人数多、官方维护积极的主题。比如：

  • NexT
  • Butterfly
  • Landscape （Hexo官方默认主题）
